# 虚拟内存与页面置换

## 一句话结论

虚拟内存让每个进程拥有**独立的、连续的虚拟地址空间**，通过页表映射到分散的物理内存，从而实现内存隔离、超出物理容量的地址空间、以及按需加载。当物理页不够时，操作系统按页面置换算法挑一页换出到磁盘。

## 标准答案

**虚拟内存解决的三个问题**

1. **隔离与安全**：每个进程有自己的地址空间，进程 A 无法访问进程 B 的内存，踩内存只会崩自己。
2. **突破物理内存容量**：程序可以使用比实际物理内存大得多的地址空间（借助磁盘上的交换区）。
3. **简化编程与内存管理**：程序员看到的是连续地址，不必关心物理内存是否连续、其他进程占了哪块。

**地址转换过程**

虚拟地址 →（MMU 查页表）→ 物理地址。页表由操作系统维护，MMU 硬件负责转换。为了加速，引入 **TLB（快表）** 缓存最近用过的页表项；为了压缩页表体积，使用**多级页表**（如 x86-64 的四级页表）。

**缺页异常（Page Fault）**

访问的虚拟页不在物理内存中时，CPU 触发缺页异常，操作系统介入：

1. 找一个空闲物理页框，没有就挑一页换出（可能写回磁盘）
2. 从磁盘把需要的页读入
3. 更新页表，重新执行触发异常的指令

注意区分：**缺页异常是正常机制**，不是错误；而**段错误（Segmentation Fault）**是访问了非法地址（页表中根本没有映射），属于真正的错误。

**页面置换算法对比**

| 算法 | 做法 | 特点 |
|---|---|---|
| 最优 OPT | 换出未来最长时间不会被访问的页 | 理论最优，无法实现，只作性能上界 |
| FIFO | 换出最早进入内存的页 | 实现简单，但会**Belady 异常**（分配的页框数增加，缺页率反而上升） |
| LRU | 换出最久未使用的页 | 接近 OPT，效果好；实现开销大（需要维护访问顺序） |
| LFU | 换出访问次数最少的页 | 可能"历史包袱"——早期频繁访问但后期不再用的页迟迟不换出 |
| Clock（NRU） | 环形扫描，访问位为 0 就换出，为 1 则清零继续 | LRU 的近似实现，开销小，实际系统常用 |

**Belady 异常**：只有 FIFO 会出现。原因是 FIFO 换出的页可能恰恰是马上要用的页，增加页框数反而改变了换出顺序。

**抖动（Thrashing）**

当并发进程太多、每个进程分到的页框太少时，进程频繁缺页，刚换出的页马上又要换入，CPU 时间全花在换页上，利用率骤降。解决办法：降低并发度（把部分进程换出到磁盘挂起）、采用工作集模型给进程分配足够的页框。

## 原理展开

**局部性原理是虚拟内存成立的前提**

- 时间局部性：刚访问过的数据很可能马上再次访问
- 空间局部性：访问了某个地址，其附近地址很可能马上被访问

正因为程序访问有局部性，才可以只把用到的少部分页留在内存里，其余放磁盘，性能依然可接受。

**多级页表为什么能省空间**

单级页表要为整个虚拟地址空间建表项，64 位下体积爆炸。多级页表只为实际用到的地址区间建立下级表，未使用的区间不分配。代价是地址转换需要多次访存（所以必须有 TLB）。

**页面大小怎么定**

页太大：内部碎片严重（最后一页用不满）、换页慢。页太小：页表项多、TLB 命中率下降。常见 4KB，也有大页（2MB / 1GB）用于数据库等需要大块连续内存的场景。

**malloc 分配内存时发生了什么**

`malloc` 申请的是虚拟地址空间，此时**并没有真正分配物理内存**。真正访问这片内存时才触发缺页异常，操作系统才分配物理页并建立映射。这也是为什么 `malloc` 很快，而首次写这块内存时会慢一点。

## 面试常问

1. **LRU 怎么实现？** 用哈希表 + 双向链表（O(1) 查找和移动）；或者用栈/计数器近似。真正的 LRU 硬件开销太大，操作系统多用 Clock 算法近似。
2. **虚拟地址空间布局？** 从低到高：代码段（.text）、数据段（.data/.bss）、堆（向上增长）、内存映射区（共享库、mmap）、栈（向下增长）、内核空间（用户不可见）。
3. **TLB 什么时候要刷新？** 进程切换时必须刷（因为换了页表），这是进程切换开销大的重要原因；PCID 技术可以给 TLB 项打标签避免全刷。
4. **什么是内存映射 mmap？** 把文件直接映射到进程的虚拟地址空间，读写内存即读写文件，省去 read/write 的系统调用和一次内核到用户的拷贝。
