# 进程与线程

## 一句话结论

进程是**资源分配的基本单位**，线程是**CPU 调度的基本单位**。线程依托进程存在，同一进程内的线程共享地址空间和资源，但各自拥有独立的栈和寄存器上下文。

## 标准答案

**核心区别**

| 维度 | 进程 | 线程 |
|---|---|---|
| 定义 | 程序的一次执行过程，资源分配的基本单位 | 进程内的执行流，CPU 调度的基本单位 |
| 地址空间 | 独立的虚拟地址空间 | 共享所属进程的地址空间 |
| 切换开销 | 大（要切换页表、刷新 TLB、切换内核栈） | 小（只需保存寄存器和栈指针） |
| 通信方式 | 需要 IPC：管道、消息队列、共享内存、信号量、Socket | 直接读写共享变量，但要配互斥锁/条件变量 |
| 健壮性 | 一个进程崩溃不影响其他进程 | 一个线程崩溃会导致整个进程退出 |
| 创建开销 | 大（需要分配独立内存空间） | 小 |

**为什么还要引入线程**

进程切换的代价太高：每次切换都要换页表基址寄存器（CR3）、导致 TLB 全部失效、Cache 命中率骤降。而线程共享地址空间，切换时这些都不用动。另外，一个程序内部往往有多个并发任务（比如一边下载一边渲染），用多进程做这件事通信成本很高，用线程共享内存则天然方便。

**线程共享什么、独占什么**

- 共享：代码段、数据段、堆、全局变量、打开的文件描述符、信号处理函数、当前工作目录
- 独占：线程 ID、寄存器上下文（含程序计数器）、栈、errno、线程局部存储（TLS）、调度优先级

## 原理展开

**线程的实现方式**

1. **用户级线程**：线程的创建、调度、切换全在用户态的线程库里完成，内核根本不知道有线程存在。优点是切换极快、不依赖内核支持；缺点是一个线程阻塞（比如发起系统调用）会导致整个进程的所有线程都被阻塞，而且无法利用多核。
2. **内核级线程**：由内核直接管理，内核知道每个线程。一个线程阻塞不影响其他线程，可以在多核上并行。缺点是每次切换都要陷入内核，开销比用户级大。现代操作系统（Linux、Windows）都是内核级线程。
3. **混合实现**：用户级线程多路复用到内核级线程上（M:N 模型），兼顾两者，但实现复杂。Go 语言的 goroutine 就是这一思路的现代版本。

**上下文切换到底切了什么**

进程切换需要保存和恢复：页表基址（CR3）、内核栈指针、通用寄存器、浮点寄存器状态，还要处理 TLB 失效和 Cache 污染。线程切换因为共享页表，省掉了最贵的那部分。

**进程间通信（IPC）方式对比**

| 方式 | 特点 | 适用场景 |
|---|---|---|
| 管道 | 半双工，只能在有亲缘关系的进程间使用 | shell 管道、父子进程简单数据流 |
| 命名管道 FIFO | 有无亲缘关系都能用，以文件形式存在 | 本机任意两进程 |
| 消息队列 | 内核维护的链表，按消息类型读取，克服了管道无格式的缺点 | 需要结构化消息的场景 |
| 共享内存 | 最快，直接映射同一块物理内存，无需内核中转 | 大数据量、高频交换（常配信号量做同步） |
| 信号量 | 本质是计数器，用于同步而非传数据 | 互斥与同步 |
| Socket | 可跨机器 | 网络通信、本机也能用 |

共享内存是最快的 IPC，因为数据只需要在进程自己的地址空间里读写，不经过内核缓冲区拷贝；但它本身不提供同步机制，必须配合信号量或互斥锁使用。

## 面试常问

1. **线程崩溃为什么会导致进程退出？** 因为同一进程的所有线程共享地址空间，一个线程踩了非法内存，内核发信号的对象是进程而不是某个线程，默认处理动作是终止整个进程。
2. **多进程和多线程怎么选？** 需要强隔离、稳定性优先（如浏览器的多标签页）选多进程；需要频繁共享数据、性能优先选多线程。实际工程常见"多进程 + 多线程"混合。
3. **协程是什么？** 用户态的轻量级线程，切换完全在用户态完成，不需要陷入内核，一个线程里可以跑成千上万个协程。适合 IO 密集型场景，但不能利用多核。
4. **进程有哪些状态？** 创建、就绪、运行、阻塞、终止。注意"就绪"和"阻塞"的区别：就绪是缺 CPU，阻塞是缺事件（如等待 IO）。
